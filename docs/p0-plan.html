P0 Implementation Plan

执行方式：当前会话顺序实施（superpowers:executing-plans）。设计依据：p0-design.html。目标：构建并在指定设备验证最小虚拟相机输入通路。

全局约束

Android API 36；Java 17 源码；Gradle 8.13、AGP 8.13.2；不依赖 Root 或系统防护变更。EGL RGBA 640×480，5 FPS 上限；仅一个后置相机；默认 30 秒，最长 600 秒；所有日志保留验证边界。

审查重点

  • 默认设备上下文不能误开物理相机。
  • YUV plane 的 rowStride / pixelStride、边界必须正确处理。
  • 异常、超时和 Ctrl+C 后不能残留实验关联或长驻进程。
  • 相机回调线程必须串行使用 EGL，释放后不继续供帧。
  • 只有真实解码且持续变化的相机帧能计入成功。

Task 1 · 可验证帧与构建基础

创建 Gradle 工程及 probe-core。接口：FrameMarker.word(counter)、sample(Y, width, height, rowStride, pixelStride)、decode(word, invertedWord)；FrameEvidence.accept(counter)。先写真实样本测试并观察失败，再实现；执行 gradlew.bat :probe-core:test 期望全部通过，提交此交付。

Task 2 · 真机生产者与消费者

创建 android-agent 的 ShellMain、VirtualDeviceAdapter、EglPattern，以及 camera-probe 的 ProbeActivity 和 CameraReader。生产者注册虚拟后置相机并按捕获请求输出标记；消费者拒绝默认设备，读取指定相机 YUV 帧并调用 Task 1 接口。执行 assembleDebug、单元测试与 lint；先以缺失有效标记为预期失败，再在真机检查相机输出是否变为连续有效帧。

Task 3 · 运维、真机验证和证据

创建 tools/Build.ps1、Inspect-Device.ps1、Start-P0.ps1。显式要求 Serial，工具检查 API、记录设备 fingerprint；只创建本次临时关联，finally 清理。安装自有测试 APK并通过系统相机权限提示启动。运行 30 秒实验并保存结构化日志，逐阶段判定；若阻断，保留异常并停止。生成 HTML 使用说明和真实验证报告。

完成条件

代码可构建、单元测试与 lint 结果明确；日志能证明通路成功或定位实际阻断；工具可重复运行且清理范围受限；文档不声称未完成的稳定性或第三方兼容性验证。最后检查 git diff --check、代码审查并提交，不自动推送。
