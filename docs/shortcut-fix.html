快捷方式与文件访问修复

验证日期：2026-10-19。图标恢复后，桌面保存和打开文件夹仍失败。最终定位到生成的 EXE 带有继承的低完整性标记，并分别修复了原生拖拽 COM 接口及异步指针捕获问题。

共同根因

生成目录继承了旧开发沙箱的 Mandatory Label\Low Mandatory Level:(I)(OI)(CI)(NW)。EXE 也继承 Low 标记，实际启动为低完整性进程 S-1-16-4096。同一 Windows 用户的 PowerShell 和 Explorer 是中完整性 S-1-16-8192。低完整性进程不能向普通完整性的 AppData、Temp 和桌面写入；其启动的新 Explorer 也出现初始化失败。

对照：同一测试程序集用低完整性 apphost EXE 运行时，AppData 和 Temp 创建目录均返回 0x80070005，仅程序目录可写；用正常的 dotnet.exe 运行 DLL 时全部通过。将测试 EXE 的标记改成 Medium 后，原来的三处目录写入全部成功。由此确认问题不是手机图标资源、普通目录 ACL 或必须管理员权限；此前对安全软件的怀疑没有证据，用户也未发现对应拦截记录。

desktop/Directory.Build.targets 在构建和发布后，仅对当前项目生成的 EXE 执行 icacls <生成的 EXE> /setintegritylevel M，不递归修改源目录、用户目录或系统文件的权限。普通用户运行即可，不要求管理员。AppData 可写性检测及程序目录回退仍作为错误恢复保留；已有回退设置会继续使用，避免位置恢复后丢失收藏和主题。

证据与验证边界

Windows System 日志在 2026-10-18 23:39:44 和 23:39:48 记录 explorer.exe 的 0xc0000142；同一分钟应用的回退目录已存在 3538 字节的豆包链接。这证明当时链接生成已完成，后续定位文件夹失败。该 Windows 事件与普通测试失败的 .NET 崩溃记录分别核对，未将测试崩溃误认为 Explorer 错误。

修正完整性后，实际 apphost 的桌面复制测试通过，并清理了本次测试链接。无线 ADB 恢复后，主界面已从 145 个真实应用中筛选计算器，右键保存成功，运行日志记录 shortcut-desktop-created，桌面生成 3586 字节的 virCre - 计算器 - V2458A.lnk。正常退出主程序及其计算器窗口后，通过该 .lnk 冷启动成功；主程序和计算器 scrcpy 各一实例。此前验证曾因无线 ADB 离线中断；设备发现现会保存已验证硬件标识，列表加载后创建链接不再重复查询手机。Windows API 测试覆盖链接回读、Unicode CF_HDROP、IDropSource COM 查询、碰撞不覆盖、错误目录降级、指针代次和已有配置保留；目录、窗口、呈现模型和旧摄像头协议回归通过。实际鼠标跨窗口拖放、全部手机和混合 DPI 仍不能仅凭这些测试宣称完成。

系统 Shell 调用存在额外等待：本次冷启动调用返回耗时 6.5 秒，部分重复调用长时间未返回，本次主动中止了最后一次等待；直接使用链接保存的目标及参数激活可正常转发。该等待的原因尚未定位，不将它归因于手机、杀毒软件或单实例实现。

运行日志

日志位于实际数据目录下的 logs\desktop.jsonl，单文件超过 256 KiB 后保留上一份。优先使用 %LOCALAPPDATA%\virCre；已有回退设置时继续使用程序目录的 virCre-data。记录操作名、时间、HRESULT、异常栈及相关本地路径，不记录手机画面、剪贴板文字或键盘输入。

操作包括 startup、shortcut-staged、shortcut-desktop-created、shortcut-desktop-copy-failed、shortcut-folder-opened、shortcut-folder-open-failed 和 shortcut-drag-failed。
