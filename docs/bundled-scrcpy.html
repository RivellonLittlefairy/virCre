源码以 Git subtree 的 squash 方式导入 third_party/scrcpy，不是嵌套 Git 仓库或 submodule。普通 clone 即包含源码；本工具的源码改动可以直接随主仓库提交。后续升级使用 subtree 合并上游版本，并同步运行时清单、DLL 名称、server 和回归测试。

当前运行时仍为官方未修改二进制，记录在 runtime-manifest.json 的 distribution=official-unmodified。这一步没有宣称已经从源码编译自定义客户端，也没有修好中文输入。输入法补丁的本地构建链路属于下一阶段。

构建与发行

pwsh -File tools/Prepare-ScrcpyRuntime.ps1
pwsh -File tools/Publish-Desktop.ps1

首次构建下载固定版本的官方压缩包；之后可使用已校验的本地缓存。脚本在写入运行时前核对整包 SHA-256，只提取清单内文件，并为每个文件记录哈希；缓存文件变化会从已验证压缩包恢复。构建脚本会把运行时复制到程序输出和发布目录下的 runtime/scrcpy。

用户应解压并保留完整目录，启动 VirCre.Desktop.exe，不能只复制单独 EXE。日常应用目录、图标读取、独立窗口及快捷方式激活都使用内置组件。手机仍需 ADB 调试授权；USB 驱动、无线配对和 USB 线缆不是 scrcpy 软件安装。历史 P0 摄像头实验及开发者单独执行的设备脚本仍有各自的工具参数，不属于本次日常启动器改造。

BundledTools 将可执行文件解析为相对程序目录的绝对路径，在子进程环境中固定 ADB、SCRCPY_SERVER_PATH 和 SCRCPY_ICON_DIR。不修改全局 PATH，不静默回退到机器上另一个 scrcpy。文件缺失时报告发布目录不完整。旧输出目录可能继承 Low 标记，构建与发布仅校正生成的主程序和两份内置 EXE 的完整性。

依赖与许可

scrcpy 的 Apache 2.0 许可保留在源码和运行时的 LICENSE.txt。根据上游构建脚本，Windows 包使用 SDL 3.4.18、FFmpeg 9.0.2、libusb 1.0.30、dav1d 1.5.4 和 ADB 37.0.1；对应许可及 ADB 原始 NOTICE 位于 runtime/scrcpy/licenses。SDL 使用 zlib 许可，FFmpeg 和 libusb 对应 LGPL，dav1d 保留原始 BSD 许可，ADB 使用官方发行包中的完整 NOTICE。

公开分发修改版时，应同时提供所用修改和 LGPL 依赖的对应源码/构建材料，并按实际构建配置核对义务。原始构建配方及依赖下载地址、版本和哈希保留在 third_party/scrcpy/app/deps。此阶段是本地开发发行目录，未发布到外部站点或创建远端 fork。

Git 连接修复

最初 Git 直接连接 GitHub，先后遇到连接重置及 443 连接失败；Windows 系统代理是 127.0.0.1:7897，PowerShell 默认使用它，而 Git 没有代理配置。为当前项目设置 http.https://github.com/.proxy 后，标签查询、源码 clone、fetch 和 subtree 导入均成功。设置只在本机项目的 Git 配置中，不随提交传播；没有更改系统代理或关闭 SSL 校验。其他电脑应按自己的网络环境配置。

验证入口与边界

dotnet run --project desktop/VirCre.Launcher.Tests
pwsh -File tools/Test-ScrcpyRuntime.ps1
dotnet run --project desktop/VirCre.Launcher.Tests -- --runtime-probe out/desktop-release
# 可选：读取真实手机应用目录
dotnet run --project desktop/VirCre.Launcher.Tests -- --device SERIAL --runtime-root out/desktop-release

验证缺失内置版本不得调用系统 PATH、指定配套 server/ADB、缺失 DLL 提前报错、无效压缩包拒绝、逐文件哈希及恢复。运行时探针清空自己的 PATH，并设置错误的外部 ADB/server 环境变量后运行发行包组件。本次六组 .NET 回归和两组脚本测试通过；发行包组件在空 PATH、错误外部环境变量下启动通过，真实手机目录返回 145 个应用（系统 37、用户 108）。另外验证了全新构建目录和包含空格的全新发布目录，两份内置 EXE 均为 Medium，空 PATH 探针通过。代码审查提出构建/发布目标只执行一次的时序风险，已拆成独立目标；原有构建输出下的新发布目录未复现 Low 标签，因此不把该风险记为已复现故障。源码与二进制版本对齐，不代表 Windows 输入法已可用。
