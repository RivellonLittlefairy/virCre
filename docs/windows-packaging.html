推荐先用 Inno Setup 生成 EXE 安装包，同时保留便携 ZIP。现有 WinUI 3 程序已有自包含发布流程，下一步是在完整发布目录外增加安装器。

如果必须交付 .msi，可以用 WiX Toolset 包装同一份发布目录。普通用户双击安装、创建快捷方式和卸载，EXE 安装器已经能满足需求。

实施日期：2026-10-19。依据用户要求新增Inno Setup安装器与一键构建脚本，迁移正式相机Java源码，制作0.1首版包。本次源码按0.1版本整理提交，并向GitHub的v0.1 Release发布成品；安装、卸载、升级与真实设备功能由用户手动验收。

本次实施与使用入口

新增packaging/virCre.iss和tools/Build-Installer.ps1，采用文中固定AppId，当前用户安装到%LOCALAPPDATA%\Programs\virCre。提供开始菜单入口、可选桌面快捷方式和系统卸载入口，默认保留用户设置、缓存与应用图标。

# 完整重编译release自定义scrcpy、发布、编译安装器、生成ZIP与SHA256。

# 仅在确认release自定义运行时已重新构建时，复用这份缓存。

输出位于out/installers/：virCre-0.1.3-win-x64-setup.exe、virCre-0.1.3-win-x64-portable.zip、virCre-0.1.3-SHA256SUMS.txt及virCre-0.1.3-build.json。每次构建使用新的package-staging目录，安装器和ZIP只来自该完整发布目录，不打包仓库、编译缓存、APK或设备日志。

构建脚本检查必需资源、runtime-manifest全部文件哈希、六个配套功能标记及release类型，统一主程序和安装器版本。按照用户“不自动测试”的要求，只做编译和文件检查，不执行测试、不启动主程序、不安装成品、不操作手机。本机Inno Setup 6.7.3工具使用官方签名安装文件的便携模式放在.cache/toolchains/inno-setup-6.7.3，不修改全局PATH。

正式相机源码的9个Java文件已复制到camera-agent/src/main/java/com/example/vircam/，与迁移前逐文件SHA256一致。Build-Scrcpy.ps1和独立agent构建脚本均改用新路径，Release客户端/server已经重新编译成功。原android/探针APK工程及根目录Gradle遗留项现已由用户手动清理，不再参与正式构建，也不会进入安装包。

成品尚未做代码签名，不能将编译成功描述为干净系统安装、覆盖升级、卸载或设备功能已验收。安装前正常关闭virCre及它打开的投屏窗口；用户可用EXE安装，或将完整ZIP解压到固定位置使用。升级或卸载还需手动确认常驻ADB占用文件时的安装器处理，不自动终止系统中的其他ADB会话。

首版0.1已完成EXE与ZIP构建，主程序和安装器文件版本为0.1.0.0；最终ZIP的561个文件已与发布目录核对，19个运行时文件SHA256通过。当前源码版本0.1.3的构建与提交记录见版本说明。安装、升级、卸载和设备功能仍由用户手动验收，不把源码编译等同安装器验收。

2. EXE、MSI、MSIX 和 ZIP 怎么选

格式适用场景本项目的取舍
EXE · 推荐面向普通用户的安装向导、快捷方式、卸载和静默安装。Inno Setup 直接收集发布目录，配置较少。默认按当前用户安装，可以避免日常安装时申请管理员权限。
MSI企业软件分发、Windows Installer 管理、组织要求统一使用 MSI。使用 WiX Toolset；需要维护组件、升级标识和安装范围，工作量通常多一些。
MSIX需要包身份、商店或组织内的 MSIX 分发。需要单独验证包身份、签名信任、子进程和桌面快捷方式路径。当前项目先不优先采用。
ZIP内部测试、免安装试用、便携分发。压缩整个发布目录即可；用户需手动解压到固定位置，没有安装器提供的卸载入口。

安装器自身是一个 EXE，程序安装后仍然是包含多个文件的目录。将全部 WinUI、.NET 和 scrcpy 组件强行合成单个应用 EXE，会增加资源和依赖问题，对当前目标没有必要。

建议成品命名：virCre-0.1.3-win-x64-setup.exe 和 virCre-0.1.3-win-x64-portable.zip。本次发布版本为0.1.3，Windows文件版本为0.1.3.0。

3. 先生成完整桌面发布目录

3.1 构建机器和用户电脑的要求不同

构建机器需要 .NET SDK 8、PowerShell 7，以及现有脚本要求的 Android SDK API 36、Build Tools、JDK。重新编译自定义 scrcpy 还需要 GCC、Meson、Ninja、pkgconf；当前脚本默认从 .cache/toolchains/msys64/ucrt64 读取工具链。完整准备过程见 现有源码构建计划。

用户电脑不需要 Android Studio、JDK、Android SDK、.NET SDK 或编译器。自包含配置负责随包带上 .NET 和 Windows App SDK 依赖。USB 驱动、手机调试授权、无线调试配对仍需按设备实际情况完成；安装器无法替代手机上的授权操作。

手机兼容性另算：当前自定义 server 的 DEX 构建指定 --min-api 36，包含虚拟摄像头的完整路径以 Android 16（API 36）为目标。Windows 安装器支持 Windows 10，并不意味着手机端也兼容旧版 Android。

是否还需要补充 Visual C++ Redistributable x64，应以干净 Windows 的实际启动结果和缺失 DLL 诊断为准。开发机上能打开程序，不能证明目标机器已经具备全部本机依赖。

3.2 当前功能应选择 Custom 运行时

Publish-Desktop.ps1 默认是 -Runtime Official，对应官方 scrcpy。当前中文输入和虚拟摄像头路径使用修改版客户端、server 及共享 Java 代码，应显式指定 -Runtime Custom。

-Runtime Custom 只选择并校验已有自定义运行时，不会自动根据最新源码重新编译 scrcpy。发布前应先完成自定义运行时构建，避免把旧缓存与新桌面程序放在一起。

下面是原方案的分步命令，包含需要用户另行决定的测试步骤；本次自动执行使用上方一键脚本，不执行测试或启动检查。手动验收时从仓库根目录执行：

Set-Location 'C:\Users\msf\AndroidStudioProjects\virCre'

# 1. 重新构建配套的自定义 scrcpy 客户端与 server。
pwsh -NoProfile -File .\tools\Build-Scrcpy.ps1 -BuildType release
if ($LASTEXITCODE -ne 0) { throw 'Custom scrcpy build failed' }

# 2. 使用全新目录，避免旧版本文件残留。
$publish = Join-Path $PWD ('out\package-staging-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
pwsh -NoProfile -File .\tools\Publish-Desktop.ps1 `
    -Runtime Custom `
    -OutputDirectory $publish `
    -GuidePage virtual-camera-window.html
if ($LASTEXITCODE -ne 0) { throw 'Desktop publish failed' }

# 3. 现有发布脚本本身会做基础检查；这里额外验证运行时哈希和无工具链 PATH 启动。
pwsh -NoProfile -File .\tools\Test-CustomScrcpy.ps1 `
    -RuntimeDirectory (Join-Path $publish 'runtime\scrcpy') `
    -RequireWindowsIme
if ($LASTEXITCODE -ne 0) { throw 'Bundled runtime validation failed' }

# 4. 先关闭已打开的 virCre，再执行启动检查。
pwsh -NoProfile -File .\tools\Test-DesktopPublish.ps1 `
    -OutputDirectory $publish -SmokeTest
if ($LASTEXITCODE -ne 0) { throw 'Desktop startup validation failed' }

Build-Scrcpy.ps1 -BuildType release 会执行现有自定义运行时检查，但其脚本中的 Meson 单元测试分支只在 debug 构建时运行。发布验收仍需另行安排相关测试，不能把 release 构建成功写成全部测试通过。

4. 推荐方案：Inno Setup 生成 EXE 安装器

从 Inno Setup 官方下载页安装编译器。2026-10-19 查看该页面时，同时提供 6.7.3 和 7.1.0；下面示例采用 6.x 常用脚本格式。编译器只需装在制作安装包的电脑上。

4.1 建议的安装行为

  • 默认目录：%LOCALAPPDATA%\Programs\virCre，当前用户安装。
  • 创建开始菜单入口，桌面快捷方式由用户勾选。
  • 在 Windows“已安装的应用”中提供卸载入口。
  • 更新时保留固定安装目录和固定 AppId，减少手机应用快捷方式失效。
  • 卸载时默认保留 %LOCALAPPDATA%\virCre 下的设置、收藏和图标；不要递归删除用户数据目录。
  • 更新和卸载前先关闭 virCre 及由它打开的应用窗口，避免仍在运行的 scrcpy 占用文件。

4.2 可供实施的完整 .iss 示例

4.3 编译安装包，并生成 ZIP

在未来实际创建了上面的 .iss 文件，并完成第 3 节发布后，继续在同一 PowerShell 会话中执行：

# 按本机实际安装位置调整。
$compiler = 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
$version = '0.1.3'
$setupDir = Join-Path $PWD 'out\installers'
New-Item -ItemType Directory -Path $setupDir -Force | Out-Null

& $compiler "/DPublishDir=$publish" "/DSetupDir=$setupDir" `
    "/DAppVersion=$version" '.\packaging\virCre.iss'
if ($LASTEXITCODE -ne 0) { throw 'Installer compilation failed' }

$zip = Join-Path $setupDir "virCre-$version-win-x64-portable.zip"
Compress-Archive -Path (Join-Path $publish '*') -DestinationPath $zip -Force

$setup = Join-Path $setupDir "virCre-$version-win-x64-setup.exe"
Get-FileHash -Algorithm SHA256 -LiteralPath $setup, $zip

预期输出是 out/installers/virCre-0.1.3-win-x64-setup.exe 和同目录的 ZIP。这里的 $publish 必须指向已经检查通过的完整目录；不要把仓库根目录传给安装器，避免把缓存、源码、设备日志等一起装进去。

现已提供tools/Build-Installer.ps1统一这些步骤。它将版本传入Publish-Desktop.ps1 -Version，调用Inno Setup后生成ZIP与校验值；只做静态文件检查，不执行功能或安装测试。

5. 如果明确需要 MSI

选择 WiX Toolset。第 3 节仍然适用，MSI 与 EXE 可以使用同一份完整发布目录。两者是不同安装系统；把 EXE 后缀改成 MSI 没有作用。

  1. 固定一个 WiX Toolset 版本，新增 WiX 工程和产品定义，明确安装到当前用户还是所有用户。
  2. 收集完整发布目录，保留相对路径，并维护 Windows Installer 组件标识的稳定性。
  3. 配置开始菜单、可选桌面快捷方式、产品版本及稳定的 UpgradeCode。
  4. 实现并验证 major upgrade 策略，检查旧版本卸载顺序、失败回滚和用户数据保留。
  5. 用标准用户与管理员场景分别测试，确认安装范围与升级规则一致。

制作成功后，MSI 的典型静默安装命令如下。/qn 不会自动授予管理员权限；所有用户安装仍需相应权限。

msiexec.exe /i "virCre-0.1.3-win-x64.msi" /qn /norestart /L*v "virCre-install.log"

当前仓库没有 WiX 工程，因此不能给出一条现成命令直接生成 MSI。普通个人分发优先完成 EXE；有企业部署要求时，再增加 MSI 更合适。

7. 什么情况才能说“安装包可以交付”

  1. 发布检查：完整目录检查、配套运行时文件哈希和主窗口启动检查通过。
  2. 干净系统：在未安装 Android Studio、.NET SDK、开发用 scrcpy 的 Windows x64 环境中完成安装与启动。静态目录检查无法覆盖这一项。
  3. 真实手机：完成调试授权后读取应用、图标、打开独立窗口，并验证当前中文输入和虚拟摄像头功能。Windows 沙盒可检查安装和启动，不能替代真实设备及 USB 通路验收。
  4. 快捷方式：开始菜单和桌面入口有效；从应用创建的手机 App 快捷方式在退出、重启及覆盖升级后仍能找到主程序。
  5. 更新和卸载：验证新装、同版本重装、旧版本升级、运行时文件占用、卸载后再次安装，以及设置和收藏的保留策略。
  6. 分发材料：确定主项目许可证，带上第三方许可和所需源码/构建材料；不要遗漏 runtime/scrcpy/licenses。

代码签名不是本地生成 EXE 安装包的前提。公开分发时建议签名并加可信时间戳，便于用户确认发布者；签名本身不保证 SmartScreen 不提示。当前检查没有验证签名、干净系统安装、覆盖升级或设备功能。

默认版本统一保存在项目根目录的VERSION文件中。Directory.Build.props让 .NET 项目读取该版本，发布脚本和安装器也从同一文件取值，界面从程序集元数据读取。更新版本时只需修改此文件；-Version仍可用于临时构建覆盖。本文出现的0.1.3是本次发布示例，对应EXE文件版本0.1.3.0。后续升级仍需验证固定目录、用户数据和快捷方式。
