Windows 输入法直接输入设计

日期：2026-10-19。状态：用户已授权实现；电脑 IME 与 Unicode 提交已接入独立预览包，等待用户手动验收。用户要求不再运行测试或使用测试 App，详见 预览版说明。

用户目标与验收含义

用户直接点击手机 App 输入框，在原独立窗口使用电脑已有的微软拼音、搜狗等输入法；输入拼音、选择候选词、中文上屏不增加额外输入框、复制按钮或发送步骤。英文、数字、退格、方向键、选择与已有快捷键应保持正常。候选框使用 Windows 输入法，手机输入法不作为主要路径。

第一轮原型必须检查 Windows 原生候选框和组词界面的可见性及位置。视频流本身不提供 Android 文本光标矩形，不能预先承诺候选框精确跟随手机文字光标。若只能显示在不便使用的位置，应明确反馈并评审后续光标信息桥接方案，不能将其标成完整的自然输入验收。

现有链路与限制

scrcpy 5.0.1 已调用 SDL_StartTextInput，并通过 SDL_EVENT_TEXT_INPUT 接收确认的文字。默认 SDK 键盘把文字发送到 Android 的 injectText，最终通过 KeyCharacterMap 转换为按键，中文和部分 Unicode 无法转换。UHID 将组词交给手机，不满足本次目标；ADB input text 也不是解决路径。

当前 Controller 的 setClipboard 支持文字和 paste 标志，可将 Unicode 文字设置到手机剪贴板并对当前显示注入 PASTE 按键。该实现使用异步按键，ACK 只确认剪贴板命令处理，不证明 App 已读取文字。多个客户端共享手机剪贴板、快速连续提交和窗口切换都可能产生竞态，必须先验证并解决。

拟采用的分层方案

  1. 本地构建：在已导入的 scrcpy 源码上建立 Windows x64 客户端构建；优先使用独立 MSYS2/MinGW 工具链，不要求普通用户安装编译器。自定义产物与官方原版分开记录来源和哈希，避免准备脚本覆盖自定义客户端。客户端与 server 保持配套版本。
  2. Windows 组词：处理 SDL 组词事件及 Windows IME 状态，输入法消费的拼音字母、候选数字、空格、回车、退格不得同时送给 Android。确认文本只发送一次；取消组词、切换英文及窗口失焦都要维护各窗口独立状态。必须检查首个字母在组词事件前到来的情况，并配对过滤 key-up，避免漏键和重复键。
  3. Unicode 提交：将已确认 UTF-8 文本直接放入控制通道，使用手机端 Unicode 粘贴路径。无需读写 Windows 剪贴板，也不伪造全局 Ctrl+V；手机剪贴板会包含已提交文字。普通 Ctrl+C/V 的既有语义保持独立。
  4. 顺序与隔离：为同一手机的提交建立可确认的串行顺序。先验证受控 server 的同步粘贴及确认机制；不能把旧异步 ACK 当作上屏成功。若仍不能避免多个窗口替换共享剪贴板，则引入按设备的共享调度，或退回评审 Android InputConnection 桥接方案，不能静默交付串字风险。

新模式先使用显式选项启用，仅对 Windows SDK 键盘生效。通过验收后再由 virCre 默认启用；原版 SDK 模式保留用于回归对照。不在 Windows 全局安装键盘钩子，不安装或切换手机输入法，不修改第三方 App。

失败、日志与边界

设备断开、窗口关闭、提交失败时，不把尚未确认的文字转给其他设备或窗口；恢复连接不自动重放旧文字。队列必须有长度与字节上限，不能静默截断 UTF-8。日志只记录失败类型与操作状态，不保存拼音、确认文本、剪贴板内容或按键序列。自定义 server 新增的日志也遵循这一点。

部分 App 或密码框禁止粘贴；剪贴板方案不能承诺绕过这种限制。若常用应用不兼容，需要向用户说明并比较 InputConnection 方案的手机安装/启用成本。本阶段不新增独立文字输入面板，也不通过点击坐标猜测手机输入框的位置。

测试与阶段推进

  1. 先跑通未修改源码的构建，核对客户端/server 版本与发行包文件完整性；清空 PATH 后验证运行。
  2. 先写组词状态机测试，覆盖开始、取消、确认、英文切换、首字母、候选数字/空格/回车和配对 key-up。增加控制消息 UTF-8、边界和顺序测试；修改 server 时补充真实提交顺序对照。
  3. 在自有可控编辑框验证“你好，virCre 123 😀”、标点、多行、连续选词、取消拼音、退格修改和中英文混输。模拟事件不能代替 Windows 原生输入法组词验收。
  4. 用真实 Windows 输入法验证候选选择，随后检查手机搜索框及常用编辑器。验证同一手机两个窗口快速切换、长文分段、复制粘贴和断线。未通过前不启用新默认模式。

此设计不宣称所有 Android 应用兼容，也不把出现候选框等同于文字正确上屏。下一步先实现本地构建和受控原型，再依据结果确认是否满足用户所说的“像英文一样自然输入”。
