virCre / Android 16 / P0

虚拟相机能力验证原型

复用用户创建的 android/ 工程。最低 Android 16（API 36），应用包名 com.example.vircam。先在手机本地生成测试帧，验证 Camera2 输入；此原型尚不采集 Windows 桌面。

真实验证记录设计实施计划

虚拟设备、显示和相机创建已在 vivo V2458A 上得到日志证明。完整 P0 必须另外取得 Camera2 读取连续变化帧的证据；以验证记录中的最新结论为准。

1. 构建

Android Studio 打开仓库下的 android/，等待 Gradle Sync。沿用 AGP 8.13.2、Kotlin 2.0.21、Gradle 8.13 和 Java 11 字节码目标；运行 Gradle 需要兼容的 JDK。编译、目标和最低 SDK 都是 36。

cd C:\Users\msf\AndroidStudioProjects\virCre
.\tools\Build.ps1

输出：android/app/build/outputs/apk/debug/app-debug.apk。这是本地 debug 签名的实验 APK。Build.ps1 执行 assembleDebug、testDebugUnitTest、lintDebug；lint 警告与真实设备通过是不同检查。

2. 检查设备

电脑需有已授权的 ADB；传输可用 USB 或已有的无线配对。不会自动配对，也不会开放新的网络端口。脚本需要 PowerShell 7，以参数数组调用外部进程并限制执行时间；ADB、scrcpy 应在 PATH 中，或用参数指定完整路径。

adb devices -l
pwsh -File .\tools\Inspect-Device.ps1 -Serial '从 adb devices 复制的完整序列号'

检查 API、型号、fingerprint、VDM / 原生 VDM / virtual_camera 服务。virtual_camera 可为按需启动的服务，因此启动前未找到不单独判定失败。多个设备时必须显式选择，脚本不猜测设备。

3. 运行一次 P0

pwsh -File .\tools\Start-P0.ps1 -Serial '从 adb devices 复制的完整序列号' -Seconds 30

默认安装或更新自有 APK。手机若弹出安装确认，需要用户允许。先在手机默认显示完成普通相机授权；虚拟设备有独立权限状态时，还会在 VirCam-P0 窗口出现系统授权页。请在系统界面允许相机。授予权限不会让探针打开默认设备的相机。

  1. 通过官方 cmd companiondevice associate 调试入口创建随机 MAC 的临时 shell 关联，取得真实 associationId。
  2. 通过 ADB 将同一 APK 作为 shell 的 app_process 类路径运行，不把 shell 权限授予普通 App。
  3. 创建带自定义相机策略的虚拟设备、960×720 显示和单个 640×480 后置虚拟相机。
  4. 官方 scrcpy 镜像该 displayId，测试 Activity 在同一虚拟设备显示启动。
  5. 普通 Camera2 App 从 YUV 平面读取二进制标记，显示灰度预览与变化帧数。手机端不会保存相机图片。
  6. 时间到后关闭相机、显示和本次镜像进程，删除本次 CDM 关联及临时 APK。

已有相同构建的 APK 可加 -SkipInstall。修改了 App 代码时需重新安装，不能用该参数跳过更新。-NoMirror 只供已有其他显示查看通路时使用，首次授权不建议开启。

时长支持 5–600 秒。关闭本次投屏窗口或 Ctrl+C 会进入停止流程；普通退出的资源释放与断连后的恢复清理都应核对日志。手机临时失联时，远程进程仍有本地 watchdog；CDM 关联与临时文件可能需要重连后清理。

4. 如何判定结果

证据含义
device-created / display-created / ready只证明注册通路可用，不能证明 App 读取了帧。
frame-submittedEGL 已向相机 Surface 提交带编号的图。
frame-readCamera2 的实际 Y 平面解出带同步头、校验和、反色副本的帧号。
input-path-verified同一会话、设备、显示和相机至少 3 帧与供帧日志对应，计数和时间戳递增，且没有终止错误。
cleanup-failed至少一个资源清理动作失败，不能把该运行判定为干净结束。

每次运行证据位于 out/<session>/，包含设备信息、shell 标准输出与异常、scrcpy 日志、App 元数据日志、result.json。App 元数据使用 run-as 读取；debug 构建不能省略。不会持久化相机像素、桌面截图、二维码内容或账户令牌。

Android 16 的虚拟后置相机对 App 映射为 ID 0，而注册端可能返回 v7_1006。ready.cameraId 是 App 可见 ID，registeredCameraId 是内部 ID。是否为虚拟相机取决于设备上下文和策略，不能只看字符串是不是 0。探针拒绝默认 displayId、默认 deviceId 和错误会话设备。

5. 测试与边界

.\android\gradlew.bat -p android :app:testDebugUnitTest :app:lintDebug
pwsh -File .\tools\Test-Tools.ps1

单元测试覆盖 Y 平面 padding、buffer position、非法尺寸、灰度不确定值、校验与反色副本错误、重复/倒退帧、16 位回绕、物理设备拒绝。宿主测试覆盖元数据不能冒充 marker 0、会话与设备匹配、终止错误、重复证据、外部进程输出与退出码、进程超时。

二维码识别、桌面输入、Windows 区域选择、第三方 App 兼容性、真实镜头遮挡对照、连续十分钟和五次启停尚需分别验证。当前代码不提供 Root、全局替换物理相机或自动确认登录功能。

6. 对应源码

  • android/app/src/main/java/com/example/vircam/shell/：shell 入口、隐藏 API 边界、EGL 供帧、关闭与 watchdog。
  • android/app/src/main/java/com/example/vircam/probe/：Camera2、帧读取和不含像素的诊断文件。
  • android/app/src/main/java/com/example/vircam/core/：纯 Java 标记、帧计数与设备上下文校验。
  • tools/：构建、只读检查、受限真机实验与证据验证。
