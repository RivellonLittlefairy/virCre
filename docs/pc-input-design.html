PC 图片与固定区域输入

2026-10-18。用户已确认：先复用官方 scrcpy，完成 PC 图片和固定区域输入，再研究窗口跟随与遮挡。已有 P0 在 vivo V2458A 上验证虚拟相机通路；本轮沿用 android/ 工程及其 API 36 下限。

目的与范围

交付可运行的 Windows 控制程序：显式选择 ADB 设备，启动已有虚拟设备与官方 scrcpy，选择 PNG/JPEG 图片或拖选固定桌面区域，显式开始、暂停和停止输入。PC 先归一化为 640×480 PNG，保持宽高比、留边，不裁切二维码。Android 接收后通过 EGL 纹理写入虚拟相机。测试 App 读取实际 Camera2 Y 平面，识别自有测试二维码，日志只保存摘要，不保存二维码正文或像素。

首版采用 .NET 8 / WinForms（本机已有 SDK），不 fork scrcpy。固定区域捕获使用 Windows GDI，明确承认可见遮挡；控制窗口或本次 scrcpy 遮挡采集区时自动暂停。没有实现取窗口背后像素、窗口跟随、H.264、第三方扫码 App 或全局相机替换。

协议 v1

ADB 显式选设备，为唯一会话的 Android localabstract socket 创建 tcp:0 本机转发；只连接 127.0.0.1。客户端发送 HELLO，双方核对版本、16 字节会话值和 deviceId，再允许数据。64 字节大端头如下；PNG 单帧最大 1 MiB，尺寸固定 640×480，首版旋转仅支持 0，其他值拒绝。

偏移字段 / 字节
0 / 4 / 6magic VCR1 / 4；version / 2；type / 2
8 / 12 / 28payloadLength / 4；session / 16；deviceId / 4
32 / 40sequence / 8；capturedUtcMs / 8
48 / 52 / 56 / 60width / 4；height / 4；rotation / 4；format / 4

消息类型：HELLO=1、FRAME=2、PAUSE=3、STOP=4、ACK=5。控制包无负载、尺寸和格式为 0；FRAME 的 PNG format=1。序号非负且同一连接递增，HELLO 序号为 0。接收器读满头和负载，先检查身份和上限，再解码；ACK 对应本次序号。发送器仅保留一个在途帧，不为慢网络积压旧帧。

生命周期

PC 输入默认暂停。每个连接须重新 HELLO；不自动重连或恢复输入。PNG 接收只保留最新 Bitmap；暂停、断开或超过 1500 ms 没有新帧时清空旧图，输出“PC INPUT PAUSED”占位图，不转用物理相机。相机捕获回调仍负责最终 EGL 提交。关闭 Windows 程序、本次 scrcpy 或显式停止会触发脚本 finally，释放消费者、socket、相机、显示、指定本机转发、临时关联和 APK。单次实验最长仍为 600 秒；失联保留清理错误及恢复线索。

文件边界与步骤

  1. 协议和背压：android :app/core 内增加 FrameProtocol、LatestFrame；desktop/VirCam.Core 提供对应协议和有界客户端。先运行截断、上限、错误身份、序号、过期帧和跨端固定头测试，观察缺失实现导致失败，再实现到通过。
  2. Android 输入：shell/DesktopReceiver 拥有 local socket 和最新图；EglPattern 增加纹理渲染与占位；保留 P0 模式。CameraReader 增加 desktop 模式和 QR 摘要证据；使用 ZXing core 识别 QR，正文不进入 UI/日志。生成两张自有测试 QR fixture。
  3. Windows 原型：WinForms 控制窗口、跨显示器物理坐标区域拖选、保持比例的 PNG 归一化、单帧 ACK 节流；CLI 验证发送两张不同 QR 和重复暂停。脚本提供 connection.json 与 stop.request 交接；转发由会话 finally 管理。
  4. 验收：Android assembleDebug、JUnit、lint；.NET Core 行为测试、Windows 构建和工具测试；真机读到两张 PC 测试二维码的预期摘要，暂停超过 1500 ms 后不能继续误报旧 QR，启停五次。固定区域由用户观察或受控桌面测试源核实；不可把静态文件发送冒充桌面捕获。
