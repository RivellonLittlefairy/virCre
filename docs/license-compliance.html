Apache 2.0 授权与分发材料

日期：2026-10-20。用户决定将 virCre 原创部分采用 Apache License 2.0。此页记录当前版本的实施范围、构建行为和验证边界。

1. 项目授权

根目录 LICENSE 是 Apache 2.0 标准全文，NOTICE 保留项目和 scrcpy 上游归属。原创代码版权属于各贡献者；scrcpy 与其他第三方内容保留其原权利人、许可和声明。Directory.Build.props 为自有 .NET 工程设置 Apache-2.0 包元数据。

Apache 2.0 本身不要求公开修改版源码。此次选择主动将匹配的完整项目源码随包提供，既便于用户审查修改，也保留依赖所需的构建材料；不能据此把 Microsoft 专有运行二进制改为 Apache。

2. scrcpy 改动声明

以 v5.0.1 / a60891aea193d92e7e5c3942700eca63f9d19a5f 为上游基线。所有当前修改过的 C、头文件、Java 与 Meson 文件顶部增加显著的 Modified for virCre (2026) 标记，原有版权和注释保留。分类和文件列表见 scrcpy 修改记录。

3. 对应源码与许可证

third_party/distribution-lock.json 锁定原样分发的 ADB、SDL、FFmpeg、libusb 二进制 SHA-256，以及 FFmpeg 9.0.2、libusb 1.0.30、SDL 3.4.18、dav1d 1.5.4 和 zlib 1.3.1 的源码包地址和 SHA-256。首次下载校验成功后缓存在 .cache/compliance-sources，发布时把真实源码包复制进成品，不仅附带远程链接。

FFmpeg 的 LGPL 2.1-or-later 状态通过实际 DLL 的 avcodec_license 等导出函数确认，构建配置也写入清单。新二进制必须通过锁文件审查；检测到 GPL/nonfree/version3 构建选项时当前流程停止。libusb 由原始发行包哈希对应到锁定版本。FFmpeg 静态依赖 dav1d 与 zlib 的许可和源码一并保留。

MinGW-w64 CRT、头文件、GCC Runtime Library Exception 与 winpthreads 许可保存在 third_party/licenses/compiler-runtime/。ADB 保留完整 platform-tools NOTICE。

每次发布从实际的 project.assets.json 和自包含 .NET 运行包读取版本，收集 license、NOTICE、ThirdPartyNotices。这样升级 NuGet 后不会静默沿用旧版微软条款；不能识别的包要求先审查。主项目 第三方说明 随成品分发。

4. 安装器和便携版

现有 Publish-Desktop.ps1 在生成目录后强制准备并检查分发材料。Build-Installer.ps1 在编译安装器前再检查一次。-SkipTests 不跳过这项分发文件检查。

pwsh -NoProfile -File .\tools\Build-Installer.ps1 -Version 0.1.1

安装器递归携带所有材料，并显示从当前微软组件原文生成的独立条款。这个条款页只对各自的 Microsoft 组件适用，不覆盖项目 Apache 授权或 LGPL 库替换和调试权利。开始菜单增加“开源许可与源码”入口。ZIP 同样包含全部材料，使用便携版前应阅读随包条款。

5. 发布前的检查

Prepare-DistributionCompliance.ps1 生成材料。Test-DistributionCompliance.ps1 检查必需文件、源码包锁、核心源码快照、Microsoft/.NET 声明和发布文件哈希。缺文件、改动材料、换入未经审查的 DLL 或使用与当前源码不匹配的自定义运行时，均应中止发布。

pwsh -NoProfile -File .\tools\Test-DistributionCompliance.ps1 -OutputDirectory '<发布目录>'
