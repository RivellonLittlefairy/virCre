电脑输入无反应：修正版

日期：2026-10-19。用户最新反馈：中文、英文和数字都没有反应；鼠标正常，没有出现“输入未确认”。此前关于出现失败标题的回答已被用户更正，不作为本次诊断依据。

已确认的代码问题与本次调整

旧预览版把所有确认文字都改为手机剪贴板加 KEYCODE_PASTE。这样一来，原本支持的英文数字也依赖应用的粘贴支持。系统同步派发成功，只能证明按键已被系统处理，不能证明目标编辑器消费了文字。没有失败标题也不能证明文字已经上屏。

  • 已确认的短 ASCII 可打印文本恢复原 SDK INJECT_TEXT 路径，不修改手机剪贴板。可打印原始按键依然不重复转发；只有 Windows 确认文本进入这条路径，避免把拼音当英文提前发出。
  • 中文、其他 Unicode 和长文继续通过原串行提交协议，改为针对目标显示发送带 Ctrl 元状态的 V 按下/松开，不再依赖专用 PASTE 键。不会在手机上按住 Ctrl；V 松开在按下结果不确定时仍会尝试派发。
  • 路径在发送前确定。失败后不自动改走另一条路径、不重放旧输入，避免重复文字。
  • 窗口重新获得焦点时，若 SDL 文本输入处于关闭状态，会尝试重新启用。

以上是代码路径修正及兼容性调整；当前没有保存用户这次会话的输入阶段日志，因此仍不能断言本次无反应的实际根因已经确定，也不能宣称已经实测修复。

打开方式

  1. 正常退出旧版 virCre 及旧版手机应用窗口。
  2. 打开 out\desktop-input-fix\VirCre.Desktop.exe，从这个主窗口的应用列表重新打开手机 App，先不要用旧发布目录的快捷方式。
  3. 点击手机 App 的输入框，观察电脑窗口标题，再尝试英文数字和中文。

标题含义

  • 电脑输入：等待按键：新模式已启用，但此会话尚未收到键盘按下事件。
  • 电脑输入：已接收按键：电脑窗口收到了键盘事件，尚未收到确认文字；中文组词时可暂时处于此状态。
  • 电脑输入：已接收文字：电脑窗口已经收到确认文字。对于英文数字，这不等同于目标 App 已显示文字。
  • 收到下一次确认文字时，会清除上一次“输入未确认”标题，避免英文数字恢复输入后仍残留旧失败提示。
  • 电脑输入：系统已派发：Unicode 提交已获得手机系统的同步派发确认，仍需观察 App 是否接收。
  • 输入未确认：队列拒绝或手机提交未被确认；不会重发。请先核对已有内容。

如果完全没有“电脑输入”字样，需要先核对是否仍在使用旧主程序或旧手机窗口。标题只显示输入阶段，不显示文字、拼音或按键序列。

日志和隐私

桌面诊断日志增加固定失败阶段：display、clipboard-lock、clipboard、paste-key、native-key。每个窗口会话每个阶段最多记录一次。不持久化任意 scrcpy 输出、文本内容、字符码、剪贴板内容、提交序号或按键序列。日志位置沿用当前用户数据目录的 logs\desktop.jsonl。

交付边界

按用户要求只修改源码、编译和打包，不运行自动化、输入模拟或真机测试，不安装测试 APK。应用列表缓存和手动刷新策略保留。禁止粘贴的编辑器仍可能不支持中文路径。
