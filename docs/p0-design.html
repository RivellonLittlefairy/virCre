virCre · P0 虚拟相机能力验证

2026-10-18。依据用户提供的《桌面画面虚拟摄像头-需求与技术路线》与已确认的 P0 设计。用户已授权实现，并要求在当前目录初始化 Git。

目的与边界

验证未 Root 的 vivo V2458A（Android 16 / API 36）中，运行于虚拟设备显示区域的自有 Camera2 App 能读取 shell 服务生成的画面。仅实现 P0，不接入照面，不创建 Windows 采集端，不修改第三方 App，不自动确认登录，不上传图像。

架构与数据流

PowerShell 工具显式选择 ADB 设备；Android shell Java 入口使用真实 shell 包身份及系统 CDM 测试入口创建的关联，调用 VDM 创建自定义相机策略的设备、显示、后置相机。隐藏 API 全部集中于反射适配层，不打包伪造的 framework 类。单线程 EGL 回调按捕获请求提交 RGBA 640×480 图像。Camera2 测试 APK 仅在非默认设备上下文打开指定 cameraId，使用 ImageReader 读取 YUV 帧。

真实性证据

生成图含彩条、方向标识、会话随机种子和递增计数的二进制标记。Camera2 从实际 Y 平面解出带校验和及反色副本的标记，记录 cameraId、deviceId、displayId、相机时间戳、标记编号和连续变化次数。服务创建成功或预览出现均不算通过；只有相机帧中的标记与服务提交编号一致，且持续递增，才形成 P0 输入通路证据。P0 不承诺二维码识别。

生命周期与失败策略

默认运行 30 秒，最长 600 秒。Ctrl+C 或超时后逆序关闭相机、显示、ImageReader 和 EGL；设备创建方 Binder 进程结束可触发系统回收。启动脚本使用 finally 删除本次 CDM 关联及本次推送的临时文件，不删除用户已有的关联。不授予普通 APK CREATE_VIRTUAL_DEVICE，不改变隐藏 API 全局策略，不回退物理相机。

测试 APK CAMERA 权限走系统正常授权；拒绝时展示原因并停止。默认显示或默认 deviceId 禁止启动探针，缺少相机或指定相机不存在时停止。ROM、角色、关联、虚拟相机服务任一环失败即记录具体阶段与异常，停止 P1 投入。清理失败必须在日志中暴露。

项目结构

路径职责
probe-core/不依赖 Android 的标记编解码、帧真实性校验及单元测试
android-agent/app_process 入口、反射适配、EGL 供帧与清理
camera-probe/普通 Camera2 测试 APK、实时诊断界面
tools/构建、只读检查、受限生命周期的真机启动
docs/HTML 设计、计划、使用说明、验证报告

验证

本地单元测试覆盖带 padding 的 Y 平面、非法大小、校验错误、反色副本错误与非递增帧。Android 构建及 lint 单独记录；真机验证记录从关联到相机读取的每个阶段，失败不冒充成功。完整验收需要遮住物理镜头并观察变化标记；连续十分钟和五次启停属于额外稳定性验收，未执行不得声称通过。

已知前置事实

只读 ADB 已确认 V2458A 在线、系统 API 36，存在 virtualdevice 与 virtualdevice_native 服务；cmd virtualdevice 没有命令实现，cmd companiondevice 有 associate / disassociate 正式测试入口。服务存在不代表虚拟相机可用。实现时保留 Android 16 AOSP 来源版本与设备 fingerprint。
