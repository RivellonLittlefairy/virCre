桌面端启动失败修复

日期：2026-10-19。问题来自发布包遗漏界面资源，没有证据表明与用户此前终止进程有关。

故障证据

启动日志显示：主窗口 InitializeComponent 抛出 Microsoft.UI.Xaml.Markup.XamlParseException，HRESULT 为 0x802B000A。程序随即退出，Windows 事件日志记录异常代码 0xc000027b。

构建目录中存在 VirCre.Desktop.pri，发布目录却没有。PRI 保存应用的 XAML 资源索引；已有的 Microsoft.UI*.pri 属于框架，不能替代应用自己的资源。仅补入应用 PRI 后，同一发布目录的程序便能创建主窗口并响应。

修复

  • 在桌面项目的 MSBuild 发布目标中，将生成的 ProjectPriFullPath 加入 ResolvedFileToPublish。资源未生成时明确报错。
  • 新增 tools/Test-DesktopPublish.ps1，检查应用 PRI、程序及必要运行时文件。正式发布脚本在报告成功前执行此检查。
  • 提供可选 -SmokeTest：实际启动发布程序，等待主窗口、确认响应，然后正常关闭。已有 virCre 进程时拒绝测试，防止单实例转发让旧程序冒充新包通过。

回归验证

  1. 修复前向全新目录发布：构建成功，但新增检查失败，明确报告缺少 VirCre.Desktop.pri。
  2. 修复后向另一全新目录发布：无需手动复制资源，发布检查通过。
  3. 对新包执行 Test-DesktopPublish.ps1 -SmokeTest：真实 WinUI 主窗口启动并响应，随后正常退出。

这次启动测试补足了此前“编译和控制台测试通过，但没有实际启动发布界面”的验证缺口。它只验证启动与正常关闭，不等同于设备读取、快捷方式拖拽或异常关闭恢复的完整 GUI 验收。

启动

运行完整发布文件夹中的 out/desktop-release/VirCre.Desktop.exe。复制或移动时保留整个发布文件夹；单独复制 EXE 会缺少依赖或界面资源。
