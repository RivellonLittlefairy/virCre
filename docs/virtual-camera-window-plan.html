事实与决策

  • 默认镜像曾随主屏关闭而 OFF，导致微信整窗黑屏。独立 SurfaceFlinger 输出使微信界面显示，但扫一扫仍黑。
  • 18:21:30 crash buffer 记录 SurfaceFlinger PresentAsyncTHD SIGABRT、Scudo 内存释放错误，随后图形系统重启/ADB断开。具体 native 根因未定；撤回手工 SF 输出实现。
  • 相机、VDM显示和scrcpy编码器改为同进程持有。复用 NewDisplayCapture 的 VirtualDisplay.setSurface 输出编码，不创建额外镜像显示。
  • PC输入约5fps，相机声明/按请求供帧最高30fps并复用最新桌面；增加流配置、首帧提交等固定诊断阶段，不记录图像或输入内容。

文件与步骤

  1. Android新增 ApplicationCameraSession，复用 VirtualDeviceAdapter、DesktopReceiver、EglPattern；复用已有 ActivityThread，保持600/615秒期限；把VD Surface接到编码器。
  2. scrcpy移除 display-mirror-independent 与 IndependentDisplayCapture；新增 vircre-camera 选项，Options/Server/NewDisplayCapture接线；构建时嵌入shell源码。普通模式默认关闭该选项。
  3. 桌面只准备CDM关联，监听所属scrcpy输出中的已验证JSON ready事件后建forward；保留精准清理与关闭失败重试。相机状态弹窗与固定阶段日志接入。
  4. 构建内置scrcpy与桌面包，输出 out/desktop-camera-direct；核对manifest、源码清理和发布文件。独立只读审查后交用户手测。

约束与审查重点

  • Android API36、用户0、单相机会话；只对当前VDM生效；窗口采集排除自身，异常暂停，PAUSE每500ms。
  • Server初始化中途失败、编码器重建、期限退出、shutdown hook与资源清理需幂等；看门狗不能与可能阻塞的close共用单线程。
  • 只按当前GUID核对远端scrcpy PID；不删除共享server jar、不杀其他窗口或真实应用进程。
  • 编译与静态审查不等于微信相机读回、扫码或稳定性通过。

按投屏分辨率修正（2026-10-19）
