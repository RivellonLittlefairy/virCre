应用列表缓存与读取优化

日期：2026-10-19。用户已选择“点击刷新时才读取手机”。本次继续遵循用户要求，只编译打包，不运行测试、不启动应用、不操作手机。

现在的使用方式

  • 首次连接一台手机时读取一次可启动应用，并保存名称、包名、系统应用标记和图标。
  • 以后启动软件、重选同一手机时，直接加载本地缓存；不自动过期、不后台全量扫描、不重新导出全部图标。
  • 手机安装、卸载、更新应用，或需要更新图标时，点击左侧“刷新设备与应用”。
  • 手动刷新失败时提示原因，并继续显示该手机原来的完整缓存。设备发现失败或授权失效时，保留当前显示的列表并禁用启动操作；恢复连接后再刷新。取消的读取不覆盖旧快照。
  • 缓存缺失或损坏时才重新读取手机；单个图标缺失时显示占位图，等待手动刷新，不触发全量扫描。

减少了哪些读取

旧链路每次运行 scrcpy --list-apps，遍历安装应用并逐包查询启动入口，再分批启动图标组件，每批最多 60 个，全部完成后才显示应用列表。

新链路直接查询手机 Launcher / Leanback Launcher 入口，不读取 GET_META_DATA，也不逐包查询启动 Intent。名称、包名、应用类型和 96×96 图标由同一个 shell 组件一次输出；不收集版本、权限、安装路径、安装时间或其他应用详情。图标继续从应用资源读取，保留之前针对 OEM 图标读取的兼容处理。

命中缓存时完全跳过上述手机应用查询、组件传输和图标导出。仍会执行轻量的 ADB 设备发现和稳定标识读取，以核对手机在线状态及缓存归属。

桌面快捷方式启动也不再扫描所有应用；仅核对目标包名的启动入口，避免为了打开一个应用而读取整台手机的应用列表。

内置自定义 scrcpy 的按包名开窗路径也改为直接查询目标应用，不再遍历所有已安装应用；兼容列表查询移除了不使用的 GET_META_DATA 标志。

缓存位置和安全边界

使用当前用户的数据目录下 app-catalog：通常是 %LOCALAPPDATA%\virCre\app-catalog，数据目录不可写时沿用软件现有的便携目录回退机制。

应用快照以手机硬件标识分开保存，图标以 PNG 内容 SHA-256 命名，并通过临时文件原子替换。无线地址变化后，只要手机稳定标识一致即可继续命中；不同手机不共用应用列表。手机未提供稳定标识时，会明确提示并跳过跨重启缓存，避免误用其他手机的数据。

图标内容相同则复用同一个文件。刷新不会先清空原快照或删除旧图标；读取、解析或缓存保存失败不会破坏上次快照。历史图标暂不自动清理。

手动验收

  1. 正常退出旧版，打开新发布目录中的 VirCre.Desktop.exe，连接手机。第一次没有新缓存，仍需读取一次。
  2. 正常退出后再次打开，确认应用列表和图标直接从缓存加载。
  3. 手机应用发生变化后，确认重开软件仍显示旧缓存；点击“刷新设备与应用”后才更新。
  4. 切换其他手机、断线刷新、无线地址变化时，确认列表归属及失败提示正确。

尚未进行实际性能计时或真机验证，因此不承诺具体启动耗时。
