真实手机应用目录

2026-10-18 · 工程首页 · 分阶段计划 · 整体设计

Windows 程序会在启动、刷新或选择设备时自行读取手机应用。名称、包名、系统/用户标记均来自所选手机。本次验证中的 145 是运行时结果，没有作为内置目录写进代码，也不会把首次读取结果永久缓存。

启动与使用

cd C:\Users\msf\AndroidStudioProjects\virCre
pwsh -File .\tools\Start-Desktop.ps1
# 已构建时：
pwsh -File .\tools\Start-Desktop.ps1 -NoBuild
  1. 让 adb devices 能看到已授权手机。程序启动后会检查设备；仅发现一台时自动选中，多台时在左侧明确选择。
  2. 等待应用列表加载。可按中文名称或包名搜索，右上显示当前过滤结果数量；底部显示所选设备和本次目录总数。
  3. 安装/卸载应用、重连手机后，点击“刷新设备与应用”重新读取。列表读取中不会保留其他设备的旧卡片。
  4. 点击星标收藏或取消；收藏页和搜索同步更新。收藏与主题目前仅在本次进程内保留。
  5. 授权、离线、超时或命令失败会显示提示。读取设备失败会同步清空旧选择，修复连接后点击刷新。

本阶段仅列举可启动的应用。打开应用按钮仍禁用；真实应用图标尚未提取，卡片使用统一占位图形。独立开窗在下一阶段实现。

程序实际调用链

环节代码与行为
UI 自动读取MainWindow.Root_Loaded → RefreshDevicesAsync；刷新按钮调用同一方法。切换设备调用 CatalogController.SelectAsync。
设备列表PhoneCatalog.GetDevicesAsync → CommandRunner 执行 adb devices -l，10 秒超时，保留在线、未授权、离线状态。
应用列表PhoneCatalog.GetAppsAsync → scrcpy -s <所选 serial> --list-apps，45 秒超时。使用参数数组，异步读取 UTF-8 输出与错误流，不弹额外控制台。
解析从实际 List of apps 段解析 Unicode 名称、行尾精确包名、* 系统与 - 用户标记；按包名去重并排序。缺头、坏条目或非零退出码均作为失败，不发布部分目录。
状态与显示CatalogController 用请求代际和取消标记隔离设备；ShellViewModel.CompleteLoad 创建显示模型，再由 WinUI GridView 展示。正常构造函数不加载 DemoCatalog。
退出关闭事件先取消并等待目录请求及设备扫描结束，再关闭最后一个窗口。CommandRunner 在取消/超时时终止并等待读取子进程退出。

真实目录仅在内存中使用；程序不会写出完整应用清单或手机画面。单元测试通过显式 preview:true 使用少量示例数据；正常首页不启用该模式。不存在从测试输出文件加载手机列表的路径。

已知验证边界

真机应用目录和实际 UI 加载已验证；多台真实手机同时切换、物理断连/重连、200% 系统文字大小、混合 DPI 跨屏移动仍未做完整实机验收。代际、错误和取消由可控服务与实际子进程测试覆盖。小屏幕高 DPI 下初始窗口高度可能超出工作区，当前可用最大化处理，自动按工作区限制首次尺寸留待调整。不能把本次 225% DPI 下正常显示描述成所有分辨率均通过。
