在 Windows 上独立使用手机 App

将当前可行性验证工程发展为手机应用桌面工具。主入口是应用列表，选择手机后可搜索、收藏、打开和管理 App 独立窗口。Windows 主界面使用用户选定的 WinUI 3，手机 App 仍在原手机运行，由官方 scrcpy 提供独立显示和输入控制。

已确认：多个不同 App 可以各自开窗；同一设备的同一 App 再次点击，切回已有窗口。虚拟摄像头保留为内部测试能力，不出现在日常启动流程。此文为设计，不代表功能已经实现或完成真机验收。

1. 首版体验

  1. 启动工具，检测已授权 ADB 设备。仅一台时自动选中，多台时由用户明确选择。未连接、未授权和离线分别提供可理解的状态与刷新入口。
  2. 选择设备后异步加载可启动应用，显示真实应用名称和包名。可以按名称或包名搜索，切换“全部应用”和“收藏”。首版使用一致的 Fluent 应用占位图标，不把占位图标冒充手机真实图标。
  3. 双击应用卡片或点击“打开”，出现该 App 的独立 scrcpy 窗口。普通启动无需安装测试 APK、创建 CDM 关联或授权测试摄像头。
  4. 不同 App 可并行开窗。在“运行中”查看本工具管理的窗口，执行“切回窗口”和“关闭窗口”。重复打开同一设备、同一包名只聚焦已有窗口；启动尚未完成时也不能重复创建。
  5. 收藏保存到 Windows 当前用户本地设置，重启后保留；收藏按包名跨设备共用，只展示当前设备已安装的匹配应用。设置文件损坏时使用空设置并提示，不阻塞启动。
  6. 关闭 App 窗口后同步移除运行记录。退出工具时请求关闭本工具创建的所有 App 窗口并等待清理；异常退出后重新打开时不冒认外部 scrcpy 进程为自己的窗口。

2. WinUI 3 主界面

标题暂用工程名 virCre，不在本轮增加品牌命名决策。采用系统 Fluent 控件、系统字体、统一圆角和间距，支持跟随系统的浅色与深色主题，以及键盘焦点与高 DPI。

位置内容
左侧导航设备选择；全部应用、收藏、运行中；底部设置。连接信息收纳在设备区。
内容顶部当前页面标题、应用数量、搜索框、刷新应用。日常页面不出现 ADB 命令、会话编号、协议字段和摄像头测试按钮。
应用内容区随窗口宽度排列的应用卡片，展示名称、低强调包名、收藏状态、打开动作。长名称截断并提供完整名称提示，空列表、无匹配、加载与失败均有独立状态。
运行中页面展示 App、所属设备、启动中或运行中状态；提供切回和关闭。外部结束、断连或启动失败及时更新，不显示为仍可操作的正常窗口。
设置主题、工具路径与基础诊断。虚拟摄像头实验通过显式命令行 --camera-lab 或开发快捷键进入旧测试窗口，默认不展示。

默认窗口 1120×760，最小 900×600；布局在 100%、150%、225% DPI 下保持可用，缩放后应用卡片和操作按钮不重叠。移动和缩放 scrcpy 窗口沿用原生窗口行为。

3. 技术方案与边界

新建 desktop/VirCre.Desktop/ 作为 WinUI 3 主程序，使用 C#、XAML、.NET 8、Windows App SDK 稳定版 1.8.260921001，首版面向 Windows 10 2004（build 19041）及以上的 x64 系统。开发依赖通过 NuGet 还原并记录确切版本；发布采用未打包、自包含目录，用户可从脚本启动，首版不要求 Microsoft Store、签名证书或 MSIX 安装。

应用数据与进程管理放在独立的 desktop/VirCre.Launcher/ 类库，通过接口隔离外部命令，避免 UI 代码直接拼接 shell。现有 VirCam.Core、Android 与 WinForms 摄像头实验保留；日常启动器不依赖摄像头实验运行。

tools/Start-Desktop.ps1 默认构建并启动新主程序；明确的摄像头实验参数进入旧程序。新设置位于 %LOCALAPPDATA%\virCre\settings.json，窗口诊断只记录退出状态、错误和对应设备/包名，不记录手机画面或输入内容。

方案选择与理由
官方 scrcpy 新显示首版使用。--list-apps 获取应用；每个窗口使用显式设备序列号、--new-display=1080x1920/420、精确包名 --start-app 和独立标题。后台命令无额外控制台，App 窗口正常可见。
现有 VDM 自建显示保留给虚拟摄像头实验。普通启动器不进入需要 CDM 与虚拟相机授权的路径。以后为特定 App 启用摄像头输入时再设计与启动器窗口的集成。
重写或 fork scrcpy首版不采用；当前列举、启动、窗口和输入能力已可复用，维护独立 UI 与会话管理即可。

首版应用窗口关闭音频转发，避免多个 scrcpy 会话重复捕获手机全局声音。音频、多开同一 App、真实应用图标、拖放传文件、剪贴板扩展、任务栏固定和自动重连不属于本轮交付。

App 复用手机现有账号和数据，独立窗口不等于独立应用实例。已有任务可能被 Android 移动到新显示；应用是否支持副屏以实测为准。主屏仍可能出现系统提示、通知或特定 App 跳转，不能承诺所有 App 完全不影响手机实体屏幕。

4. 生命周期和错误处理

  • 应用列表解析保留中文、空格和特殊字符；以行尾包名为标识，区分用户/系统应用标记并去重。命令失败、格式异常或超时显示失败，不把部分结果当完整列表。
  • 所有外部命令使用参数数组，显式选择 ADB 序列号。列设备超时 10 秒，列应用超时 45 秒；刷新与切换设备取消旧任务，旧结果不能覆盖新设备列表。
  • 窗口管理键为 (serial, packageName)。先登记“启动中”再创建进程，避免连续双击重复开窗；启动后等待有效窗口，30 秒内失败则回收本次进程并显示可重试错误。
  • 切回已有窗口时先恢复最小化，再请求系统前台焦点；Windows 拒绝激活时提示用户从任务栏切回，不谎报成功。
  • 关闭单个窗口先发正常关闭请求，最多等待 8 秒，仍未退出则终止本工具持有的对应进程。不会 force-stop 整个 App 包，不调用 adb kill-server 或 forward --remove-all。
  • 默认采用 scrcpy 的虚拟显示销毁内容行为；正常关闭时由 scrcpy 回收本次显示。异常退出时查询并记录残留可能性，不能仅凭本地进程退出就声称手机端全部清理成功。
  • 设备切换后旧设备的窗口继续在“运行中”按设备区分；设备离线时标记异常，停止对该设备发新启动请求。重连后由用户刷新，不自动重新打开 App。

6. 验收标准

  1. WinUI 3 主程序可以构建并正常启动；初次运行可显示正确设备及真实应用列表，普通流程不弹摄像头探针授权。
  2. 应用名称和包名都可搜索；收藏经过退出、重启仍存在；无连接、拒绝授权、搜索无结果、列表失败和损坏设置均有可恢复状态。
  3. 同一手机的两个不同测试 App 可以同时独立开窗；记录实际 displayId，确认不是把主屏镜像两次。重复打开同一 App 不新增 scrcpy 进程或显示。
  4. 切回窗口、最小化恢复、手动关窗、运行中关闭和主程序退出的状态一致；只有本工具创建的进程会被关闭。
  5. 至少一次真机测试观察手机主屏与 App 窗口的关系；如主屏发生系统提示或任务迁移，按实记录，不做全 App 兼容性承诺。
  6. 执行 Launcher 行为测试、WinUI 3 构建、PowerShell 语法检查和 git diff --check。保留现有协议测试；本轮不修改 Android 时不重复索取安装或摄像头授权。
  7. 核对浅/深主题、中文长名称、键盘操作与高 DPI 实际布局；构建成功与视觉通过分别记录。首版不以功能按钮堆叠代替主界面设计。

当前已完成的前置核实：本机具有 .NET SDK 8.0.419 与 scrcpy 5.0.1；vivo V2458A / Android 16 的 scrcpy --list-apps 返回中文名称与精确包名。传统 Windows Kits Include 路径未发现，WinUI 3 的实际构建与启动仍需在实施阶段验证。

7. 保护既有工作

保留用户对 android/settings.gradle.kts、android/gradle/wrapper/gradle-wrapper.properties 的修改；不提交旧的根目录 gradle/ 产物。摄像头实验不会因启动新主页自动运行，已验证的 PC 输入能力仍可单独使用。
