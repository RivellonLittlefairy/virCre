WinUI 3 手机应用工具 · 实施计划

目标：先交付可启动、可交互的 WinUI 3 界面壳子，再分次接入真实手机能力。用户要求“一次一次去做”；本次只实施阶段一，完成后等待实际界面反馈，不连续推进后续阶段。

架构：WinUI 3 主程序位于 desktop/VirCre.Desktop；可测试的界面状态位于 desktop/VirCre.Presentation；真实设备与窗口进程在后续阶段落到独立 Launcher 模块。既有 WinForms 摄像头实验保留。

技术：C# / .NET 8 / WinUI 3 / Windows App SDK 1.8.260921001，Windows x64、未打包自包含运行。文档统一 HTML。当前会话顺序执行；保留用户 Android 配置与根目录 gradle/。

阶段交付物完成标准状态
一：界面壳子主窗口、应用/收藏/运行中导航、示例卡片、搜索、临时收藏、主题与空状态。真实 WinUI 3 程序可启动；示例数据明确标注；交互与视觉检查通过。本次实施

阶段一 · 任务 1：可测试的界面状态

文件：新增 desktop/VirCre.Presentation/{AppCard,ShellViewModel}.cs、VirCre.Presentation.csproj；新增 desktop/VirCre.Presentation.Tests/{Program.cs,VirCre.Presentation.Tests.csproj}。

接口：AppCard 提供只读 Name、PackageName、Glyph、IsFavorite；ShellViewModel 提供只读可观察 Apps、Query、Page、Title、Description、EmptyTitle、EmptyDescription、IsEmpty，以及 Navigate(string)、Search(string)、ToggleFavorite(string)。本阶段所有数据来自固定 DemoCatalog，不读取设备、不写用户设置、不启动手机 App。

  1. 先写行为测试并运行至失败：名称与包名搜索、中文与大小写、清空搜索恢复、收藏切换、空收藏和运行中状态、旧页面状态不串到新页面。
  2. 实现最小状态模型；应用集合与收藏状态从拥有者操作，不暴露可写集合供 UI 随意修改。
  3. 运行 dotnet run --project desktop/VirCre.Presentation.Tests，期望全部 PASS。

审查重点

  • 示例卡片不能显示为手机已连接，禁用操作不能暗示手机 App 已打开。
  • 收藏页切换及取消收藏后，搜索结果、数量和空状态同步；搜索只影响当前页面。
  • 中文长名称、包名和大字号不挤压收藏与动作按钮；小窗口仍可滚动访问内容。
  • 高 DPI 与系统主题切换后标题栏、背景和内容保持清晰，不出现白底黑字残留或遮住窗口按钮。
  • 默认启动新 WinUI 3 壳子；旧摄像头实验只能显式进入，本阶段不连接手机、不增加安装授权。
