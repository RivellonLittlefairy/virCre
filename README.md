# virCre

virCre 支持在 Windows 桌面以独立窗口操作 Android 手机应用，提供鼠标与键盘输入、应用收藏，以及带应用原始图标的桌面快捷方式。应用实际仍在手机上运行。

virCre 还支持将投屏窗口覆盖的桌面内容作为虚拟摄像头输入，供手机应用的扫一扫等相机功能读取。

[下载最新版](https://github.com/RivellonLittlefairy/virCre/releases/latest) · [0.1.3 更新说明](docs/release-0.1.3.html)

## 使用说明

### 1. 下载并安装

电脑需运行 Windows 10 2004（19041）或以上版本的 x64 系统。普通应用窗口以 Android 10（API 29）及以上为兼容目标，虚拟摄像头需要 Android 16（API 36）及以上。Android 10～15 手机会自动使用普通模式，旧系统的具体兼容性仍需真机验证。

在 Releases 页面选择以下任一版本：

- **安装版**：下载文件名以 `-setup.exe` 结尾的安装包，运行后从开始菜单打开 virCre。默认安装到当前用户目录，通常不需要管理员权限。
- **便携版**：下载文件名以 `-portable.zip` 结尾的压缩包，完整解压到固定位置，运行 `VirCre.Desktop.exe`。请保留整个目录。

安装版和便携版均内置 ADB、修改版 scrcpy、.NET 和 WinUI 运行依赖，无需额外安装 Android Studio 或 scrcpy。USB 驱动安装和手机调试授权仍需由用户完成。当前安装包未进行代码签名。

升级前，请先关闭 virCre 及其打开的手机应用窗口，再安装新版本或替换便携版目录。

### 2. 连接手机

首次使用建议通过 USB 连接：

1. 在手机开发者选项中开启 USB 调试。
2. 连接电脑，解锁手机，在手机提示中允许这台电脑进行调试。
3. 打开 virCre，点击左侧“刷新设备与应用”，选择对应手机。

virCre 也支持已完成配对并建立连接的无线 ADB。目前不提供自动无线配对功能；使用期间需保持调试连接在线。

同一手机同时通过 USB 和无线 ADB 连接时，程序按已确认的硬件标识合并为一个设备，新窗口优先使用在线 USB 连接。刷新后按手机身份保留选择并复用已有应用窗口；已有会话不会在两种连接间自动迁移。无法确认硬件标识的连接不会仅凭机型合并。

首次连接时需要读取手机应用及其图标。后续启动优先显示本地缓存，不重复进行全量扫描。手机安装、卸载或更新应用后，点击“刷新设备与应用”即可更新列表。

### 3. 打开应用与输入

点击卡片上的“打开应用”，或双击应用卡片，即可打开独立窗口。新窗口采用手机屏幕比例，初始大小根据电脑可用空间调整，支持拖动和缩放。

点击手机应用的输入框后，即可使用电脑键盘输入。中文输入支持使用电脑输入法完成组词和选词。

顶部搜索框支持按应用名称或包名筛选，点击星标可收藏常用应用。“运行中”页面支持切换至已打开的窗口或关闭窗口；界面主题可在“设置”中调整。

当前应用窗口不转发手机声音。部分应用对虚拟显示、相机权限或输入事件存在额外限制，兼容性取决于手机系统和具体应用。

### 4. 创建桌面快捷方式

将应用卡片的图标、名称或空白区域拖至桌面，或右键点击卡片并选择“创建桌面快捷方式”。星标和“打开应用”按钮不支持拖动创建快捷方式。

双击快捷方式可直接打开对应的手机应用，无需先打开 virCre 主界面。手机需保持在线并已授权调试；连接失败时，程序会显示主界面及失败原因。对应应用已打开时，将切换至现有窗口。

快捷方式引用当前程序目录。移动便携版目录或从测试版切换至安装版后，需在新位置重新创建快捷方式。

### 5. 使用桌面画面作为手机相机输入

“设置 → 虚拟摄像头 → 打开应用时启用虚拟摄像头”默认开启。如需使用普通应用窗口，可关闭此选项。该设置仅对新打开的窗口生效；已打开的应用需关闭并重新打开，以切换模式。

连接 Android 10～15 手机时，程序自动禁用虚拟摄像头，设置页显示不支持的原因；应用列表和桌面快捷方式均以普通模式打开应用。此行为不会覆盖支持设备的相机默认设置。

[Android 版本兼容说明](docs/android-compatibility.html)

使用时，将需要读取的桌面内容置于投屏窗口下方，再在手机应用中打开扫一扫或其他相机功能。若出现摄像头权限提示，请在投屏窗口中授权。输入画面随窗口移动和缩放，采集范围为手机画面实际覆盖的桌面区域，不包含投屏窗口自身、标题栏和窗口黑边。

- 目标帧率可在设置中调整，范围为 1～30 fps，默认 15 fps，支持运行期间修改。实际帧率取决于电脑、手机和连接状况。
- 窗口靠边或跨屏时继续采集，跨屏部分按桌面位置拼接，屏幕外的部分补黑。
- 窗口最小化、电脑锁屏或临时采集失败时，程序等待采集条件恢复；还原窗口、解锁或恢复采集后自动继续。手动暂停后需手动恢复。
- 可在“运行中 → 相机画面”查看状态、暂停或继续采集。ADB 断线会结束会话，恢复连接后需重新打开应用。

目前仅支持同时打开一个启用虚拟摄像头的应用窗口，正常运行无固定时长上限。虚拟摄像头仅对该虚拟设备中的应用生效，不影响手机主屏应用使用物理相机。

[虚拟摄像头详细说明](docs/virtual-camera-window.html)

### 手机息屏与输入响应

手机亮屏并解锁后，在电脑应用窗口按 **左 Alt+O** 可关闭手机物理面板；按 **左 Alt+Shift+O** 可恢复面板。

关闭物理面板与系统锁屏是不同状态。手机进入休眠或锁屏后，部分应用控件仍可能无法响应输入，该兼容性问题尚未完全解决。

### 设置、缓存与日志

主题、收藏、相机设置、应用目录缓存和快捷方式图标默认保存在 `%LOCALAPPDATA%\virCre`。卸载时默认保留这些数据。请勿单独删除快捷方式引用的图标文件，以免已有快捷方式无法显示图标。

运行日志位于该目录下的 `logs/desktop.jsonl`。画面仅在内存中处理，程序不保存桌面截图、录像、输入文字或剪贴板内容。

## 技术原理概览

### 独立窗口和电脑输入

Windows 主程序使用 WinUI 3 和 .NET 8，负责设备选择、应用目录、设置和窗口管理。

打开应用时，virCre 通过 ADB 启动手机端的 scrcpy 服务，在 Android 虚拟显示中运行应用。手机对虚拟显示画面编码并传回电脑，电脑将鼠标和键盘事件发送至手机。电脑窗口与手机主屏可显示不同内容，应用执行和账号数据仍由手机承载。

项目内置修改版 scrcpy 客户端及配套服务端。电脑输入法负责中文组词和选词，确认后的文本通过扩展控制通道发送至手机并派发。普通鼠标、按键和窗口操作沿用 scrcpy 的控制链路。

### 应用目录、图标和快捷方式

读取应用列表时，程序通过 ADB 在手机上运行 Java DEX 导出器，使用 Android 的 PackageManager 获取可启动应用及其原始图标，并将结果传回电脑。该过程无需安装额外 APK 或获取 root 权限。

应用目录按手机缓存，图标按内容保存；界面从缓存读取，刷新时才重新访问手机。桌面快捷方式通过 Windows Shell API 创建，链接指向 virCre，并携带要打开的手机应用信息和持久图标路径。

### 虚拟摄像头画面传输

Windows 端使用 Windows Graphics Capture 采集显示器，投屏窗口通过系统接口排除自身，避免画面递归。程序按照投屏内容区的物理桌面坐标裁切，多屏时拼接，再编码成 JPEG，经 ADB 数据通道发送到手机。

手机端的 `camera-agent` 嵌入 scrcpy 服务端，通过 Android 16 的 VirtualDeviceManager 创建虚拟设备和虚拟摄像头。接收的桌面帧经解码和 EGL 渲染后提交至相机 Surface，供该虚拟设备中的应用通过相机接口读取。应用显示直接连接 scrcpy 编码器，无需额外创建镜像显示。

当前传输链路采用逐帧 JPEG，涉及桌面采集、图像缩放、网络往返、手机解码和纹理上传。目标帧率不代表应用最终显示或分析的帧率；跨屏采集、高分辨率和较慢的无线连接均会增加处理或传输开销。

### 源码和开发入口

| 目录 | 职责 |
| --- | --- |
| `desktop/` | WinUI 界面、设备与应用管理、缓存、独立窗口和桌面采集 |
| `android-agent/` | 应用目录与图标导出器 |
| `camera-agent/` | 嵌入 scrcpy 服务端的虚拟设备、相机与桌面帧接收逻辑 |
| `third_party/scrcpy/` | 修改版 scrcpy 客户端和服务端源码 |
| `packaging/`、`tools/` | 构建、自包含发布、安装器和分发材料检查 |

构建需要 .NET SDK 8、PowerShell 7、Android SDK API 36、Build Tools、JDK，以及 GCC、Meson、Ninja；制作 EXE 安装包还需 Inno Setup 6。完整命令和检查范围见 [Windows 打包说明](docs/windows-packaging.html)，内置组件的来源和修改见 [scrcpy 说明](docs/bundled-scrcpy.html)及[修改记录](docs/scrcpy-changes.html)。

默认版本号统一保存在根目录的 `VERSION` 文件中，程序、安装器和发布脚本自动读取；界面使用程序集中的版本信息。更新默认版本时只需修改该文件，临时构建仍可通过 `-Version` 覆盖。
