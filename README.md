# virCre

在 Windows 上把手机 App 当作独立窗口使用：鼠标点击、电脑键盘输入、收藏常用应用，也可以把 App 拖到桌面，生成带原始图标的快捷方式。应用仍然在手机上运行。

virCre 还可以把电脑窗口下方的桌面内容送进手机 App 的虚拟摄像头，例如让手机上的扫一扫读取电脑画面。

[下载最新版](https://github.com/RivellonLittlefairy/virCre/releases/latest) · [0.1.2 更新说明](docs/release-0.1.2.html)

## 怎么用

### 1. 下载并安装

电脑需要 Windows 10 2004（19041）或以上的 x64 系统，手机需要 Android 16（API 36）或以上。

在 Releases 页面选择一种下载：

- **安装版**：下载文件名以 `-setup.exe` 结尾的安装包，运行后从开始菜单打开 virCre。默认安装到当前用户目录，通常不需要管理员权限。
- **便携版**：下载文件名以 `-portable.zip` 结尾的压缩包，完整解压到固定位置，运行 `VirCre.Desktop.exe`。请保留整个目录。

ADB、修改版 scrcpy、.NET 和 WinUI 运行依赖已内置，不需要另外安装 Android Studio 或 scrcpy。USB 驱动和手机上的调试授权仍需自行完成。当前安装包未做代码签名。

升级前，先关闭 virCre 和它打开的手机应用窗口，再安装新版或替换便携目录。

### 2. 连接手机

首次使用建议先用 USB 连接：

1. 在手机开发者选项中开启 USB 调试。
2. 连接电脑，解锁手机，在手机提示中允许这台电脑进行调试。
3. 打开 virCre，点击左侧“刷新设备与应用”，选择对应手机。

也支持已经配对并连接的无线 ADB。virCre 目前不会自动完成无线配对；手机必须保持调试在线。

首次读取应用和图标需要一点时间。之后启动会优先显示本地缓存；手机安装、卸载或更新 App 后，再点击“刷新设备与应用”，不会每次启动都全量扫描。

### 3. 打开应用和输入

点卡片上的“打开应用”，或双击应用卡片，即可打开独立窗口。新窗口跟随手机屏幕的比例，初始大小会适应电脑可用空间，也可以自行拖动和缩放。

先点击手机 App 的输入框，再使用电脑键盘输入，中文可以直接用电脑上的输入法组词、选词。

顶部搜索框可以按应用名称或包名筛选，点击星标可以收藏常用 App。“运行中”页面可以切回或关闭已经打开的窗口；主题在“设置”中调整。

当前窗口不转发手机声音。部分 App 对虚拟显示、相机权限或输入事件有额外限制，兼容性会因手机系统和 App 而异。

### 4. 把 App 放到电脑桌面

把应用卡片的图标、名称或空白区域拖到桌面；也可以右键卡片，选择“创建桌面快捷方式”。不要从星标或“打开应用”按钮开始拖动。

以后双击这个快捷方式，就能直接打开对应手机上的 App，无需先打开 virCre 主界面。手机需要在线且已授权调试；连接失败时会显示主界面和原因。同一个 App 已经打开时，会切回原窗口。

快捷方式引用的是当前程序目录。移动便携目录、从测试版换到安装版后，需要在新版中重新创建快捷方式。

### 5. 使用桌面画面作为手机相机输入

“设置 → 虚拟摄像头 → 打开应用时启用虚拟摄像头”默认开启。只想使用普通应用窗口时，可以关闭这个选项。开关影响之后新开的窗口，已经打开的 App 需要关闭后重开才能切换模式。

使用时，把需要给手机 App 读取的电脑内容放在投屏窗口下方，再在手机 App 中打开扫一扫或其他相机功能。若出现摄像头权限提示，在投屏窗口中允许即可。输入画面跟随窗口移动和缩放，取自手机画面实际覆盖的桌面区域，不包含投屏窗口自身、标题栏和窗口黑边。

- 设置里可以调整目标帧率，范围为 1～30 fps，默认 15 fps，运行中也能修改。实际帧率取决于电脑、手机和连接情况。
- 窗口靠边或跨屏时继续采集，跨屏部分按桌面位置拼接，屏幕外的部分补黑。
- 最小化、电脑锁屏或暂时采集失败时等待恢复；还原窗口、解锁或恢复采集后自动继续。主动点击的“暂停”仍需手动继续。
- 在“运行中 → 相机画面”查看状态、暂停或继续。ADB 断线会结束会话，恢复连接后需重新打开应用。

目前同时只能打开一个启用虚拟摄像头的应用窗口。正常运行没有固定时长上限。相机只对这个虚拟设备中的 App 生效，手机主屏上的物理相机保持原来的用途。

[虚拟摄像头详细说明](docs/virtual-camera-window.html)

### 手机息屏后，有些按钮点不动？

先让手机亮屏并解锁。在电脑应用窗口按 **左 Alt+O**，可以只关闭手机物理面板；按 **左 Alt+Shift+O** 恢复面板。

面板黑了不等于手机锁屏。手机真正休眠或锁屏后，部分 App 控件仍可能不响应，这个问题尚未完全解决。

### 设置、缓存和日志放在哪里？

默认保存在 `%LOCALAPPDATA%\virCre`，包括主题、收藏、相机设置、应用目录缓存和快捷方式图标。卸载默认保留这些数据。不要单独删除快捷方式引用的图标文件，否则已有链接会失去图标。

运行日志位于这个目录下的 `logs/desktop.jsonl`。画面只在内存中处理，程序不保存桌面截图、录像、输入文字或剪贴板内容。

## 技术原理概览

### 独立窗口和电脑输入

Windows 主程序使用 WinUI 3 和 .NET 8，负责设备选择、应用目录、设置和窗口管理。

打开 App 时，virCre 通过 ADB 启动手机端的 scrcpy 服务，在 Android 虚拟显示中运行应用。手机将这个显示的画面编码后传回电脑，电脑再把鼠标和键盘事件发回手机。电脑窗口与手机主屏的显示内容因此可以分开，App 的执行和账号数据仍在手机上。

项目内置了修改版 scrcpy 客户端和配套服务端。电脑输入法负责中文组词、选词，确认后的文本通过扩展的控制通道交给手机派发。普通鼠标、按键和窗口操作沿用 scrcpy 的控制链路。

### 应用目录、图标和快捷方式

读取应用列表时，通过 ADB 在手机上运行一个 Java DEX 导出器，使用 Android 的 PackageManager 获取可启动应用及其原始图标，再把结果传回电脑。这个过程不需要安装额外 APK 或获取 root。

应用目录按手机缓存，图标按内容保存；界面从缓存读取，刷新时才重新访问手机。桌面快捷方式通过 Windows Shell API 创建，链接指向 virCre，并携带要打开的手机应用信息和持久图标路径。

### 桌面画面怎样进入虚拟摄像头

Windows 端使用 Windows Graphics Capture 采集显示器，投屏窗口通过系统接口排除自身，避免画面递归。程序按照投屏内容区的物理桌面坐标裁切，多屏时拼接，再编码成 JPEG，经 ADB 数据通道发送到手机。

手机端的 `camera-agent` 嵌入 scrcpy 服务端，通过 Android 16 的 VirtualDeviceManager 创建虚拟设备和虚拟摄像头。收到的桌面帧经解码、EGL 渲染后提交到相机 Surface，运行在该虚拟设备中的 App 就能从相机接口读取画面。应用显示直接连接 scrcpy 编码器，避免额外建立一块镜像显示。

这条链路目前逐帧传输 JPEG，包含桌面采集、图像缩放、网络往返、手机解码和纹理上传。目标帧率不等于 App 最终显示或分析的帧率；跨屏、高分辨率和较慢的无线连接都会增加负担。

### 源码和开发入口

| 目录 | 职责 |
| --- | --- |
| `desktop/` | WinUI 界面、设备与应用管理、缓存、独立窗口和桌面采集 |
| `android-agent/` | 应用目录与图标导出器 |
| `camera-agent/` | 嵌入 scrcpy 服务端的虚拟设备、相机与桌面帧接收逻辑 |
| `third_party/scrcpy/` | 修改版 scrcpy 客户端和服务端源码 |
| `packaging/`、`tools/` | 构建、自包含发布、安装器和分发材料检查 |

构建需要 .NET SDK 8、PowerShell 7、Android SDK API 36、Build Tools、JDK，以及 GCC、Meson、Ninja；制作 EXE 安装包还需 Inno Setup 6。完整命令和检查范围见 [Windows 打包说明](docs/windows-packaging.html)，内置组件的来源和修改见 [scrcpy 说明](docs/bundled-scrcpy.html)及[修改记录](docs/scrcpy-changes.html)。
